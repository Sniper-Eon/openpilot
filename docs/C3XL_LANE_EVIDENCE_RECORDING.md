# C3XL 本地完整日志与广角抽帧

2026-10-15。用途：把广角画面、模型车道曲线、高德推荐车道和转向响应放在同一时间线上分析。不改变转向参数或导航变道条件。

## 最终实现

设备 `/data/continue.sh` 设置 `export C3XL_LANE_EVIDENCE=1`。只有精确值 1 启用；关闭后恢复 C3XL 原来的精简记录。

- loggerd 保存完整 rlog.zst 与原有 qlog.zst，包含 modelV2、导航和车道消息。原生相机时间及模型时间均保留。
- 新增 lane_evidenced 进程，行车时每秒保存一张广角画面、原始尺寸、帧号、拍摄单调时钟，以及模型几何、导航、广角相机状态和标定的各自时间戳。各服务是独立采样，离线必须按实际时间检查偏差，不能把它们假设为完全同步。
- 广角采样最大 640×480，保留 NV12 色彩数据，zlib 压缩；不是连续录像，也不是原分辨率图像。文件按分钟结束，运行中的最后一分钟为 .partial，正常停车关闭后改为 .jsonl；即使中断，已 flush 的完整行仍可恢复。
- 抽帧存储目录 `/data/media/0/lane-evidence/`，仅清理本工具自己的旧文件，总量上限 512 MiB，包含遗留 .partial；磁盘可用空间低于 2 GiB 时暂停写入。完整 rlog 仍采用原有磁盘清理机制，不受此 512 MiB 上限约束。
- 采集模式下 uploader 不运行；记录先留在设备本地，不依赖 Mac 或网络。高德推荐车道只有手机实际发送时才会记录，工具不会补造。
- C3XL 原生 encoderd 继续关闭：本次隔离硬件编码测试出现 VIDIOC_QBUF failed，不能声称标准广角 HEVC 录像可用。改用上述低频抽帧避免依赖该编码器。

## 实际验证

车端 loggerd 单目标编译成功。

设备缺 pytest，未额外安装软件，改用独立 OPENPILOT_PREFIX 和 LOG_ROOT 的原生测试，不触及车辆实际导航或相机通道：

1. 开关为 0：无 rlog，保留精简策略。
2. 开关为 1：生成 rlog，modelV2、navAssistStateSP、laneTopologyStateSP 各回读 20 条，模型四条车道线与两条道路边缘曲线保留。
3. 使用隔离的模拟广角帧，实际新录制进程保存 6 张 640×480 画面，时间戳及相机状态保留，NV12 数据可以解压回读。
4. 本地 11 项测试通过：明确开关、停车不采集、普通设备不受影响、本地上传策略、文件轮转、权限、低空间停止写入、旧片段及中断文件限额清理。

上述为合成输入链路验证，不能当作真实道路识别或性能验证。尚需下次接车进入行车状态，确认真实画面与模型日志文件持续增长。设备停车时 loggerd 和 lane_evidenced 都不运行属于预期。

## 备份与回退

原文件、原 loggerd 二进制和原 `/data/continue.sh`：`/data/codex-install-20261013/lane-evidence-backup/`。

本轮只部署记录相关源码与二进制，不将分支其他视觉实验一并安装；设备 Git HEAD 保持原值，不冒充完整分支升级。

停车后可把启动脚本中的采集开关改成 0，再重启程序停止后续采集。关闭后原有 uploader 策略会恢复，若要继续让历史记录只留本地，应先取回处理记录或单独继续阻止 uploader。

## 用户操作

无需装新 APK 或 Mac 软件。接车后打开现有导航转发，先停车保持设备在行车界面，确认新 rlog 和广角抽帧开始增长后再正常人工驾驶。不要为采集特意进行变道。结束后从设备取回同一时段数据，用 Mac 对照标注。
